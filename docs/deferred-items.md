# Deferred Items

Every item a phase's design or checklist explicitly pushed to a later phase, consolidated so it is not lost
between a phase's own design, plan and checklist files.

**The file is one table.** It holds the deferrals that are still live — nothing in it has been built, and
every row is either unscheduled with a trigger a reader could observe firing, blocked on something no phase
ships, or open by design.

No count of the table is written down here, because a written count is a second source of truth that the
next reader has to maintain. Derive one:

```bash
# rows still deferred
awk '/^## Still deferred/{f=1} f' docs/deferred-items.md | grep '^| ' | grep -vc '^| Item |'
```

**Where this file came from.** It was the `## Deferred Items Log` section of
[`work/mvp/2026-07-23-nodejs-sdk-v1-roadmap-design.md`](./work/mvp/2026-07-23-nodejs-sdk-v1-roadmap-design.md)
until 2026-08-31. The roadmap's own rule (its "How Phases Get Executed" section) is that the document records
phase *status* and nothing else, and it named this log as its one **exception** — an exception that only
existed because there was nowhere else to put a cross-phase register. There is now: this file, beside
`open-items.md` and `deviations.md` at the `docs/` root. The roadmap keeps its dated status notes and links
here.

## The three registers, and which one an item belongs in

| Register | Holds | Item is |
|---|---|---|
| `deferred-items.md` (this file) | Work a phase decided **not to do yet**, with the phase that owns it | Scheduled, or explicitly unscheduled with a trigger |
| [`open-items.md`](./open-items.md) | Everything found to be unmet, unverified, misreported, or surprising | A gap between what is claimed and what is built |
| [`deviations.md`](./deviations.md) | The as-built audit of the deviation ledger | A place this port deliberately differs from the reference contract |

The boundary is *when the item was created*, not what it is about. A deferral is a decision made **before**
the work: "not this phase, that one." An open item is a discovery made **after**: "this is not what the
checklist says it is." The same question can legitimately sit in both. Removing the `DomainModelError` class
tier is a row here, because Phase 3b decided not to do it yet; it is also `R.E2` in
[`open-items.md`](./open-items.md), because a later audit found the mixed taxonomy that decision left behind.
Two acts, two registers, one breaking API change to make.

## Maintenance

Every phase's brainstorming session checks this file for rows targeting it before starting, and appends any
new deferral it produces before the phase is considered done. That is how a decision made in Phase 0 ("we
will handle `NFR-2` properly once adapter packages exist") does not silently evaporate by Phase 8.

**A row leaves the table once its deferral is built, closed, or settled as won't-fix**, so the table states
what is still outstanding and nothing else; the rows removed before 2026-09-04 are reproduced verbatim in
[`work/mvp/2026-09-04-register-retirement-purge.md`](./work/mvp/2026-09-04-register-retirement-purge.md).

**Cite a row by its key, never by its line number.** Cite the backticked requirement ID or the row's topic.

A phase's own deferral section stays in its design or checklist. They are **upstream provenance**, the dated
record of what that phase decided, and this file is the aggregate they feed. Deleting them would delete the
provenance; the rule is that nothing may be *only* in a phase document.

**Counted 2026-09-01, with the rule stated because three readings give three answers.** Under
`docs/work/mvp/`: **11** headings carry the exact title `## Deferred Items (add to the roadmap's Deferred
Items Log)`; **16** match `^## Deferred Items` at all, adding three bare `## Deferred Items` and one
`## Deferred Items Produced by This Phase` alongside the roadmap's own now-stubbed `## Deferred Items Log`;
and **22** match `^## Deferred`, adding five `## Deferred out of …` variants. The audits below walked the 16.

```bash
grep -rlE '^## Deferred' docs/work | sort     # the widest reading, 22 files
```

**The rule was being broken, twice.** The 2026-08-31 audit walked those sections against this table and found
three items that had never made it here; all three were appended, marked as recovered. Six more had reached
`open-items.md` instead, which is the right register for what they became — `PIPE-40`/`REDIR-22` are its G1 —
and they stay there. The 2026-09-02 re-audit then found four more that had never reached this file, one of
them inside a document the first audit had already walked. See the dated note at the end.

## The 2026-09-02 re-audit

A read-only pass re-verified every row against the working tree rather than against each row's own text.
**No deferral had evaporated** — every row whose target phase had shipped either had the work in the tree or
had the non-delivery recorded in a register, and all ten phases have shipped. The register did the job it
exists to do; its *prose* had drifted. Of the rows above, four were unscheduled and carried no trigger at all
against this file's own rule, and four citations named a `## Deferred Items` heading or an unrelated line
rather than the row they meant. Every one of those corrections is preserved inside the row it belongs to,
which is why so many rows carry a dated note mid-sentence. Four items were also found that had never reached
this file: three were appended, and the fourth — Phase 8a's `sendfile(2)` revisit trigger — was folded into
the zero-copy file-dispatch row.
